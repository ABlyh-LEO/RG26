### 布局缺陷（开发中发现并修复）

实现列式赛程图时发现了七个会导致界面**看起来是错的**的缺陷，均已修复并加测试：

| 缺陷 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| **宽度自反馈** | 画布宽度膨胀到 **914 万像素**，卡片挤成一条线 | `measure()` 用 `board.clientWidth` 算列宽，而 board 宽度正是由列宽决定的 —— 测量→改宽度→再测量的正反馈 | 可用宽度改从**滚动容器** `scroller.clientWidth` 取；`ResizeObserver` 也改为观察滚动容器 |
| **列 body 用全局高度** | 滚动区高达 **12141px**（画布只有 6216px），内容溢出画布，视觉上糊成一团 | 每列的 `.bracket__column-body` 都设成全局 `maxHeight`，而节点是绝对定位在 body 内的 → 矮列的 body 撑爆容器 | body 高度改为**本列**的 `columnHeights[key]` |
| **阶段混装 / 纵向错开** | 先出现"决赛被顶到画布顶端"，加分段后又变成瑞士轮与决赛上下分家、中间一大片空白 | 一度把排位赛（44 张卡 ≈ 5000px）与瑞士轮、决赛塞进同一条纵向带 | 见下方「完整性取舍」 |
| **八强首轮拆成两列导致连线横穿** | 四条连线（`F-L1B→F-L2A`、`F-L1A→F-L2B`、`F-W1A→F-WSF`、`F-W1B→F-WSF`）各自横穿一整列无关卡片，看起来像"连错了" | 胜者组与败者组其实是**同一轮**的比赛，且交叉向前喂给下一轮；按依赖深度拆成左右两列就必然产生跨列边 | 合并为一列「八强赛」；跨列边改为走**列间通道**，不横穿卡片 |
| **多条连线重叠成一条** | 同一段间隙里 **5 条线共用同一个竖直 x**，重叠后看起来"少了几条线" | 折线的竖直段取固定的 `midX`，与同一通道内的其他线完全重合；先前用 `min(lane*step, span/2)` 时后面的车道又被上限夹到同一 x | 新增 `laneOffset()`：通道内**严格单调**铺开，任意两条车道 x 互不相同；列间距由 12px 增至 **`GAP = 64`** |
| **最下方比赛被裁掉且滚不到** | 390×844 下画布高 1177px、内容实际到 1441px —— 最下面一场**看不见，也滑不到** | 画布高度改取 DOM 实测值 `measuredHeight` 后，`heights` 状态却只在 `columns`/`connections` 变化时更新：窄屏 `columnWidth` 收敛到 `minColumnWidth`，卡片变窄、队名多换一行，节点真实高度超过记录值，而画布高度跟着那个偏小的实测值走。又因 `overflow-x: auto` 会把 `overflow-y: visible` 提升成 `auto`，超出的部分被直接裁掉 | 画布高度改为 `Math.max(layout.totalHeight, measuredHeight, FALLBACK_HEIGHT)`，其中 `totalHeight` 按**当前** heights 算出，保证不会低于真实内容；并在 `columnWidth` 变化后也重新测量 |
| **两种颜色的连线交叉处糊在一起** | 胜者实线与败者虚线在通道里交叉时颜色互相污染，分不清哪条是哪条 | 连线半透明（0.35 / 0.45）且线宽 2px，交叉处两层颜色叠加 | 先画一层**背景色外衣**（`.bracket__link-casing`，4.5px）再画彩色线，交叉处下层线被"切断"一小段；线宽降到 1.5px（≥900px 为 1.75px）、提高不透明度 |
| **不同晋级路径的连线共线重叠** | 图上**看起来只有一条线，却代表两条不同的晋级路径**；基线实测 **12 处**同 y 共线重叠，最长一处 **250px** | 车道偏移（`laneOffset`）过去只作用于**竖直段**的 x，**水平段从来无人管理**。两条线的竖段 x 分得开，横线却落在同一个 y 上完全重合。最严重的一类甚至不在横穿段，而在**进入段**：`F-W1A→F-WSF` 从八强赛 (cy 370.99) 出发，而「败者组第二轮」的 `F-L2B` 恰好也在 cy 370.99，两段横线在 x=1376..1440 通道里完全重合 | 新增 `reserveHorizontal(通道 x, 高度 y, 步长)`：**每一段横线**（进入 / 横穿 / 离开）都按 `(通道, 高度)` 登记占用并左右交替找最近空位；跨列与相邻列连线**共用同一套 `laneCount`**（两套计数各自从 0 开始会撞出 74px 的竖直重叠）；穿越高度的评分改为按**腾挪后的实际落点**计算，避免"先挑最好再硬挪"把线顶到 720px 之外。结果：**12 → 3 处**，剩余 3 处全部是同一卡片扇出的豁免情形；最大绕行比 1.41，竖直折返 0 |

> 这些缺陷都不报错、不崩溃，只是静静地画出一张**语义错误**的图。
> 因此对应的 e2e 断言写在「列排布」「整体高度」「各列 body 高度必须不同」
> 「同一 x 上不得有两条竖直连线」「**同一 y 上不得有两条水平连线共线**」
> 「最下方比赛不被裁掉」上，而不是「元素是否存在」。
>
> 「同一 y 不得共线」这条断言是**后补的**：先前只断言了竖直段，
> 于是共线重叠这个 bug 一直没有被测出来。在补上它之前，
> 不得声称连线已修好。
