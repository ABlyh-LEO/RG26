# 2026-10-03 特殊赛果验证：0:0、弃权、判负

## 问题（用户提问）

> 弃赛，判负，以及 0 比 0 依然会分胜负等，这些特殊情况可以正确处理吗？

## 结论

**核心情形全部正确**（48 项端到端检查通过，已固化为 28 项回归测试）；另有 4 处边界需要口径或提示，其中 3 处本次已处理。

## 1 逐项验证结果

| 情形 | 结论 | 证据 |
| --- | --- | --- |
| **0:0 仍然分胜负**（§3.2.2 S3） | ✅ 正确：比分原样保存 `0/0`（不补假分、不当成未录入），双方时间自动记 **360 秒**，胜者必须由裁判指定 | 录入接受；统计 A=0、B=50、P=25、T=360、n=1、胜者 W=1；不给胜者被拒（不允许平局） |
| **未开赛弃权** | ✅ 正确：不填积分即可录入；落库积分为 `null`（误填也会被丢弃）；n=0、不计 A/B/P/T，但 W/L、m、O 照常计入 | 统计断言 + 校验 0 错误 |
| **行政判负中止** | ✅ 同上；胜者可以是任一方（由裁判指定） | 同上 |
| **弃权累计晋级** | ✅ 正确：附一六「胜负仍计入战绩」，三场弃权累计 3 胜即达到晋级条件、停止参赛，且不产生任何假分 | 3 胜断言 + n=0 断言 |
| **缺分 / 缺时间** | ✅ 正确：有效比赛缺一方积分被拒；积分不为 0 却缺时间被拒；一方 0 分可省时间并自动 360 | 三条断言 |
| **决赛 BO1 / BO3 小局** | ✅ 同类情形一致：0:0 + 胜者、弃权、判负均可录入，且整份数据通过校验；0:0 计入系列赛比分 | 4 项断言 |
| **重赛覆盖弃权** | ✅ 正确：弃权后重赛追加记录、历史保留、统计只按重赛计算（附一一「重赛只取最终有效场次」） | 断言 + 校验 0 错误 |
| **退赛导致分组奇数** | ✅ 正确：停止自动配对并报因，**不擅自轮空**（既有 D18 用例） | — |

## 2 本次处理的 3 处边界

1. **判负方向没有校验、也没有提示** → 把"被判罚方"自己填成胜者会被静默接受，胜负会记反。
   本次在录入界面「结果类型」下方增加**按类型变化的录入口径提示**：判负必须选未被判罚的一方、弃权选到场完成比赛的一方、0:0 也要选胜者并说明 360 秒约定（`src/operator/ResultWorkbench.tsx`）。系统仍然不代判——这是既定原则。
2. **`finals.ts` 注释与校验自相矛盾**：注释写「BO2 允许平局（表演赛）」，但 schema/校验要求"已确认小局必须有胜者"、录入接口也拒绝无胜者的局。
   表演赛在本系统里按**活动**处理、不进录入队列，所以真正一致的模型是"录入的每局都要有胜者"。本次**按事实改写注释**（不改校验，避免为不可达路径放宽门禁）。
3. **口径文档缺失** → [RULES.md](../RULES.md) 新增「特殊赛果：0:0、弃权、判负」小节（含四类情形的积分/时间/胜者/是否计入 A/B/P/T 对照表），[OPERATOR_GUIDE](../OPERATOR_GUIDE.md) 新增「三种容易录错的情况」。

## 3 仍需组委会口径的 1 处（未改代码）

**双方都无法上场（双弃权）**：赛制要求每场都有胜者，系统因此**无法登记**。
建议口径：由组委会公布处置（例如记其中一方胜并附说明，或作废该场并调整后续对阵），**不要**用假 0 分或空结果绕过校验。已在 RULES.md / OPERATOR_GUIDE 写明。

另外记录一条**有意的门禁**：排位赛中某队弃权或无法出成绩时，该队没有可比成绩，**自动定榜会被拒绝**，必须由裁判组走「人工覆盖」录入名次并填写来源说明（这就是"豁免信道"的用途）。

## 4 新增回归测试

`tests/domain/special-results.test.ts`（28 项）：0:0 的录入/时间/统计/校验、弃权与判负的录入与统计口径、误填积分被丢弃、缺分缺时间被拒、一方 0 分自动 360、弃权累计晋级、决赛 BO1 与 BO3 小局同类情形、重赛覆盖弃权，以及两条**已知限制**（判负方向无法校验、双弃权无法登记）。
