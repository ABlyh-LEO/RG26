# 2026-10-02：CI、Pages 与移动晋级图修复

本记录说明本次修复与本地验证结果；提交推送后，远端 CI 和 Pages 部署状态以 GitHub Actions 实际运行结果为准。

## 修复内容

### CI 与 Pages 路径

原测试使用 `/#/...` 导航，会丢弃 Pages 的 `/RG26/` 前缀。构建步骤的 `VITE_BASE_PATH` 也不会自动传入后续的 `vite preview` 进程；preview 重新读取配置时可能使用根路径，与被测产物不一致。

- 浏览器导航、数据读取和公开资源检查保留同一个 base。
- `scripts/serve-subpath.mjs` 将已有生产产物挂载到指定根路径或子路径；缺失 JS、JSON 和维护入口返回真实 404。
- CI 和部署均设置 `E2E_SKIP_BUILD=1`，直接检查上一步的生产构建，不覆盖待发布文件。
- 部署触发范围包含测试、静态服务脚本及其配置；仍须全部必需检查通过才部署。
- 新增 7 个静态服务测试，覆盖 MIME、子路径、查询参数、404、重定向和目录边界。

### 测试的数据与时间依赖

`.meta-bar` 在加载数据前就存在，原来的可见性检查不能证明数据就绪。等待条件改为元信息中出现真实数据时间，再检查页面标题。

6 个依赖“赛前未公布”状态的测试使用经过 schema 校验的合成快照，并固定赛前日期；其余用例继续读取实际生产快照。这样正常录入抽签、对阵和比赛结果或日期推进时，不会仅因测试假设仍停留在赛前而阻止发布。

### 移动晋级图

连线原来在 React 渲染期间读取旧 DOM，而卡片位置在随后提交时才改变。窄屏、旋转和内容换行会造成连线滞后一轮；卡片采用绝对定位，仅观察外层容器也无法捕捉其高度变化。

- DOM 提交后用 `useLayoutEffect` 测量卡片并生成连线，使二者使用同一版布局。
- 保留卡片高度的小数像素，避免多张卡片累加取整误差。
- 同时观察滚动容器和各卡片尺寸，响应旋转、成绩更新、长队名和字体变化。
- 保留横向滚动和既有晋级流向，不修改赛制或正式结果。
- 新增 2 个浏览器回归场景：首次加载、360/390/844/1440px 切换、横向滚动、比分刷新和字体放大。直接检查 SVG 端点位于对应卡片边缘、同列卡片无重叠、末行未越过画布底部。

## 复现

在仓库根目录运行；环境变量写法为 Bash，PowerShell 对照见部署指南。

```bash
npm ci
npx playwright install --with-deps chromium webkit
npm run typecheck
npm run lint
npm run test

# CI 根路径
npm run build
E2E_SKIP_BUILD=1 npm run test:e2e

# Pages 子路径；此步骤会重建 dist，不要在根路径测试仍运行时执行
VITE_BASE_PATH=/RG26/ npm run build
E2E_SKIP_BUILD=1 E2E_BASE_URL=http://127.0.0.1:4173/RG26/ npm run test:e2e
```
