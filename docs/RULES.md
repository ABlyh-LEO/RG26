## 1 时间与权威性

原文明确说明：**以下时间仅供参考，具体情况以赛程组共享文档当天安排为准。**
目前未提供该共享文档地址（记录在 `event.openItems`）。

本工具的行为约定：

- 所有时间以带时区偏移的 ISO 8601 存储（例如 `2026-10-03T09:00:00+08:00`）。
- 显示一律按赛事时区 `Asia/Shanghai`，**不跟随访问者所在时区**。
- 当地时间经过计划开始点，**不会自动**把比赛标记为「正在进行」或「已结束」。
  这种情况显示为「等待现场确认」。
- 计划时间、修订后的计划时间、实际时间三者分开存放，日程调整不破坏结果身份。
- 结束时间未知时为 `null`，**绝不编造**占位时刻；依赖关系用 `afterSeriesId` 表达。

| 赛段 | 规则 | 正常数量 |
| --- | --- | --- |
| 排位赛 | 22 队按三审排名顺序各跑两轮（上午/下午，两场地并行），取两轮最优成绩排 1–22 名；前 16 晋级 | 44 次单队跑图 |
| 瑞士轮 | BO1，3 胜晋级、3 败淘汰，最多 5 轮 | 8 + 8 + 8 + 6 + 3 = 33 场 |

## 3 瑞士轮统计口径

### 3.1 两种统计集合（必须严格分开）

对每队：

| 符号 | 含义 |
| --- | --- |
| `n` | 计入得分表现的**有效比赛**数量 |
| `m` | 已结算并登记的**对阵**数量（含未开赛弃权与行政判负中止） |
| `W`、`L` | 上述对阵的胜负数量 |
| `s_k`、`o_k` | 第 k 场本队 / 对方的**最终有效原始积分**（不封顶写回） |
| `d_k` | `s_k − o_k` |
| `t_k` | 开赛后首次达到最终有效积分的时间（**建筑须经稳定确认**）；零分局记 360 秒 |

| 结果类型 | 计入 A/B/P/T | 计入 W/L、m、O |
| --- | --- | --- |
| `normal` 有效正常比赛 | ✅ | ✅ |
| `early-end` 按规则提前结束 | ✅ | ✅ |
| `walkover-before-start` 未开赛弃权 | ❌ | ✅ |
| `administrative-stop` 行政判负中止 | ❌ | ✅ |

**是否计入由结果类型推导**，不靠手工勾选组合，避免出现互相矛盾的记录。

### 3.2 「已登记对阵」的口径

按**已经确认结果**的有效对阵计入本次结算。
下一轮**仅公布但尚未完赛**的配对**不提前计入 O**。

> 这是本工具的解释（原文写「m 为已登记对阵场数，按每场对应对手计入一次」）。
> 若组委会有不同解释，应递增 `rules.version` 并调整本节。

### 3.3 关键约束

- 瑞士轮**每场必须有明确胜者，不允许平局**。
- 胜者**由裁判确认**，不根据积分高低自动推断。
  维护工具把「建议胜者」与「正式胜者」分开。
- **缺分不等于 0**，不得用假 0 分填补缺失数据。
- 重赛只纳入**最后有效**的那一次；旧记录保留并标记为被取代。
- 输入积分与秒数用规范化非负十进制字符串存储并保留实际精度；
  拒绝负数、非数字、非有限值；**原始积分不设 16 分上限**。
- 时间大于 360 秒只提示复核，**不据此新增硬性判罚**（原文未明确时间字段总范围）。

## 4 公式

以下公式已对照 DOCX 内置数学结构（OMML）逐项核读。

```text
局均得分 = Σ s_k / n
局均分差 = Σ d_k / n
T       = Σ t_k / n

A = (100 / n) × Σ( min(s_k, 16) / 16 )
B = (1 / n)   × Σ( 50 + 5 × clamp(s_k − o_k, −10, +10) )
P = (A + B) / 2

v_j = W_j / (W_j + L_j)
q_j = 50 × v_j + 0.5 × P_j
O   = (1 / m) × Σ q_j        （按每场对应对手计入一次）
R   = 0.6 × P + 0.4 × O
```

### 计算顺序

1. 先计算**所有**队伍的 `P` 与 `v`。
2. 再遍历对手记录计算 `O`、`R`。
   `O` **不依赖**对手的 `O` 或 `R`，因此是单遍的。

### 边界值

| 条件 | 结果 |
| --- | --- |
| `n = 0` | `A = B = P = 0`，`T = 360` |
| 无胜负记录 | `v = 0` |
| `m = 0` | `O = 0` |
| `n = 0` 时的局均得分/分差 | 显示「—」（原文未规定默认值） |

`A`、`B`、`P`、`O`、`R` 均在 0–100 之间。

### 原文简例（作为回归测试 D01）

某队两局积分为 18、0，对手为 12、10：

- 分差为 `+6`、`−10`
- `A = (100 + 0) / 2 = 50`（18 封顶为 16 → 100；0 → 0）
- `B = (80 + 0) / 2 = 40`（`+6 → 50+30=80`；`−10 → 50−50=0`）
- `P = 45`
- 若两名对手的胜率为 `0.5`、`1`，`P` 为 `60`、`70`，
  则 `q` 为 `55`、`85`，`O = 70`，`R = 0.6×45 + 0.4×70 = 55`

该例已实现为自动化测试（`tests/domain/scores.test.ts`）。

### 数值精度

- 在 `src/domain/rational.ts` 中实现小型有理数运算：
  规范化 BigInt 分子/分母、十进制字符串解析、加减乘除、比较、显示格式化。
- 公式里的 `0.6`、`0.4`、`0.5` 分别使用 `3/5`、`2/5`、`1/2`。
- **比较使用交叉相乘**，不用 epsilon 把不等值强行视为相等。
- **只在展示阶段保留两位小数**，排序一律使用原始计算精度。
- 序列化时把分子/分母转为字符串（不能直接 `JSON.stringify` BigInt）。

## 5 排序与配对

### 同战绩组排序

依次比较，**前项相同才比较后项**：

1. `R` **高**者在前
2. `P` **高**者在前
3. `T` **小**者在前
4. 排位赛最终名次**靠前**者在前

按原始精度排序，公布时保留两位小数。
**页面显示的四舍五入值不参与排序。**

不增加未规定的「直接交手」「净胜分优先」等规则。

### 配对

- **R1**：按正式排位首尾配对 —— 第 1 名对第 16 名、第 2 名对第 15 名……第 8 名对第 9 名。
- **R2 起**：按相同胜负战绩分组，组内按上述规则排序，
  依次「第 1 名对第 2 名、第 3 名对第 4 名」相邻配对。

配对组顺序（按赛程初始化）：

| 轮次 | 组顺序 | 正常场次 |
| --- | --- | --- |
| R2 | `1-0`、`0-1` | 4 + 4 |
| R3 | `2-0`、`1-1`、`0-2` | 2 + 4 + 2 |
| R4 | `2-1`、`1-2` | 3 + 3 |
| R5 | `2-2` | 3 |

组内场次顺序就是排序后的相邻配对顺序。

### 停止条件与轮次门禁

- 达到 3 胜或 3 败后**停止参赛**。
- 每一轮**全部结束且确认后**才生成下一轮正式候选。
- 正常场次预期为 `[8, 8, 8, 6, 3]`，**不能为了凑数伪造比赛**。
- 若退赛等导致某组人数为奇数、名单异常或名额变化：
  **停止自动配对并显示原因**，允许有说明的组委会修订，**不擅自轮空**。
- 原文**没有**「避免重复对阵」的规定，因此**不实现**自动避重、跨组调队、随机配对或轮空。

### 第三轮整轮冻结

R3 必须在 **R2 确认后一次性发布全部 8 场对阵和时间槽**。
不得根据本轮前四场结果重新排序后四场；当前赛程没有第三轮跨日安排。

### 赛程图展示约定

晋级页默认按阶段、轮次查看；完整图通过独立入口打开。完整图分为瑞士轮与决赛两段，保留 33 场瑞士轮和 14 场决赛。排位赛的 44 次单队跑图在排位赛视图查看，因其仅通过最终排名产生 16 个晋级名额，不画成逐场连接。

决赛由**胜者组、败者组、冠军争夺**三个独立画布呈现：

| 分区 | 画布中的比赛顺序 | 跨区关系 |
| --- | --- | --- |
| 胜者组 | 第 1、4、2、3 场 → 第 7、8 场 → 第 11 场 | 败者转入相应后续比赛；第 11 场胜者直达第 14 场 |
| 败者组 | 第 5、6 场 → 第 10、9 场 → 第 12 场 | 来源和去向以卡片按钮显示 |
| 冠军争夺 | 第 13 场 → 第 14 场 | 第 13 场来自第 12 场胜者与第 11 场败者 |

排列服务于晋级线路的可读性，真实场次号、时间及赛事依赖不变。14 场比赛的 20 条依赖全部保留：11 条区内胜者实线、9 条跨区关系。跨区来源／去向按钮可以直接定位、聚焦关联比赛；不把败者路线横穿其他分区。手机可在各分区独立横滑，页面本体不横向溢出。

同一目标比赛的两条区内胜者线采用树形汇合，共用通道中心和真实目标端点。共同末端允许重合；不能将它们强制错开成不同车道，否则会在入卡前制造十字交叉。瑞士轮保留独立路径算法；未公布的配对不画出确定晋级关系。

布局根据真实卡片尺寸计算，容器宽度从滚动区测量、每列使用自身高度、画布覆盖最下方卡片；字体变化、横竖屏和赛果刷新后重测。回归检查真实端点、十字交叉、错误共线、折返、裁切及页面溢出。详见[分区改版](acceptance/2026-10-02-bracket-clarity.md)和[树形汇入修复](acceptance/2026-10-02-bracket-junctions.md)。

| 八强双败（决赛场次） | 蓝方 | 红方（**不反向**） |
| 决赛 BO3 的**每一局** | **蓝方（全系列固定）** | **红方（全系列固定）** |

**BO3 全系列不换边**，包括总决赛名额争夺战和总决赛：第 1–3 局均为第一席位蓝、第二席位红。晋级卡仅在每队旁标一次颜色，比分按系列赛胜局数展示。

**决赛 12 场 BO1 不换边**（只有一局）。

BO3 先赢两局即结束；2:0 后第三局显示“免赛”或“无需进行”，不显示不存在的出场颜色，不补录比分。此项调整只改变红蓝方归属与说明，不交换已记录的参赛席位、积分、用时或胜者，也不改变瑞士轮奇偶轮规则。

BO3 晋级图在每队旁只标一次固定蓝／红方，保留系列赛比分及免赛说明，不重复列三局颜色表。比赛详情的小局行同时展示该局实际成绩与红蓝方；工作台按局独立录入成绩，但红蓝归属保持固定。

**关键性质：红蓝方完全由赛程结构推出，不落库、不需要人工维护。**
实现见 `src/domain/sides.ts`，观众端与工作台共用同一规则。对阵尚未公布时不编造队伍：决赛图可标记已知的席位颜色；瑞士轮未公布卡片只说明第一、第二席位的颜色规则，不把颜色归给未知队伍。当前实现与回归证据见[BO3 固定红蓝方验收](acceptance/2026-10-02-bo3-fixed-sides.md)。

### 到达最终分时间

**必须记录，且为强制必填**（组委会确认），BO1 与 BO3 的每一局都要：

- 瑞士轮存 `homeReachedSeconds` / `awayReachedSeconds`（attempt 层）
- 决赛每局存同名字段（`games[]` 层，2026-10 补齐 —— 此前这张表
  没有时间字段，决赛成绩的时间信息无处可存）

用途：**积分相同时，最后得分时间是判断本局胜负的重要依据。**

**唯一例外是零分局**：积分为 0 时沿用 360 秒约定（见上文 `t_k`），
**自动补上**，不需要手填。弃权与行政判负不计表现分，因此不要求时间。

**「没填」与「0 秒」是两件不同的事**：有效比赛留空会被**拒绝保存**，
绝不静默存成 `null` 或伪造成 0。

### 决赛场次序号

竞技组决赛按实际比赛顺序编号 1–14，详见上方固定对阵图。展示演出与表演赛不参与编号。未决出的名额写「第 7 场败者」等来源说明，卡片标题使用对应序号，不向观众展示 `F-W1A` 等内部标识。

### 展示组是单独演出，不是对阵

展示组的三场正式演出**不是比赛**：没有对手、没有比分、没有胜者，也不计入任何排名。

| 项目 | 展示组演出 | 竞技组对阵 |
| --- | --- | --- |
| 数据表达 | 只登记**演出队伍**（`showcaseTeamId`）；席位来源 `slots` 与"参赛双方"快照 `participantSnapshot` 保持 `null` | 两个席位来源 + 参赛快照 |
| 界面 | 单队卡片，第二个位置显示「单队展示」 | 双方对阵、比分、胜者 |
| 校验 | 不适用"自我对阵"与"必须有胜者"检查；若数据里出现胜者则报错 `showcase-winner` | 严格检查自我对阵、胜者必填、胜者须为参赛方 |

抽签只决定**演出顺序**，不产生任何对阵；不要把同一支队伍写进两个席位来表示"单队演出"。

### 对阵未确定时如何展示

赛程图上还没确定的对阵，**必须说明"在等什么"**，不能填一个看起来像真的名次。

| 情况 | 数据表达 | 界面显示 |
| --- | --- | --- |
| 上一轮结果未确认 | `slotRef` = `pending` + 原因 | 「等待第 1 轮结果确认后公布」等 |
| 依赖某个系列赛 | `winner` / `loser` | 「第 8 场败者」 |
| 八强种子未公布 | `finals-seed` | 「八强第 1 名」「八强第 8 名」 |
| 排位赛名次已锁定 | `qualification-rank` | 「排位赛第 3 名」 |

要注意 **`qualification-rank` 只在名次真正锁定后才用**。瑞士轮尚未公布时，
整列不该出现「排位赛第 1 名 vs 排位赛第 2 名」这种配对 —— 那不是赛程，
只是把槽位编号念了一遍。

### BO3 小局

- 小局与系列赛**分开记录**。
- 每局确认胜者后累加系列赛比分，**先达到 2 胜即结束**。
- `2–0` 后第三局标记为**「不需要进行」**，不能当作 0–0 未完赛。
- **不能在系列赛尚未产生胜者时向下游推进。**

### 已晋级/淘汰队伍的指标

已晋级、已淘汰队伍的**胜率和 P 按实际已赛成绩保留**，
其 `O` 仍随历史对手后续成绩更新。

**因此两支 3-0 队伍不能在 R3 当晚就永久确定 W1/W2** ——
最终种子要等 **R5 全部结束后**统一计算。

## 7 状态与更正机制

### 三个独立维度

| 维度 | 取值 |
| --- | --- |
| `executionStatus`（现场进程） | `scheduled` / `ready` / `running` / `finished` / `delayed` / `cancelled` / `not-needed` |
| `resultStatus`（结果） | `none` / `provisional` / `confirmed` |
| `publicationStatus`（公布） | `draft` / `published` / `superseded` |

- 维护工具中的**草稿只保存在本机**。
- 正式站点的数据只能来自**通过校验并发布**的快照。
- 观众可以看到明确标注的「待确认成绩」，
  但它**不能参与正式配对或晋级**。
- 当地计划时间已过，**不得自动**把比赛标成正在进行或已结束。

### 排位赛定榜门禁

排位赛名次只有在**显式定榜**之后才是「正式名次」。规则如下：

| 概念 | 含义 | 能否用于晋级判定 |
| --- | --- | --- |
| 当前排行（实时榜） | 由**已确认**成绩现场派生，随成绩变化 | **不能**。只能展示，且必须标注「实时 · 成绩不完整／未确认，不作为晋级依据」 |
| 正式名次 | 由一次显式定榜动作写入并持久化 | 能。R1 配对、八强种子、优秀奖结算只读它 |

定榜的两条路径：

1. **按成绩定榜**（推荐）：每支竞技组队伍都必须有至少一条**已确认且积分可比较**的
   成绩。少一支队伍就无法定榜，系统会列出缺谁。并列（积分与用时完全相同）或
   只录到一轮的成绩会写入复核记录，并列必须填写复核说明。
2. **人工定榜**：裁判组直接核分录入名次时，**必须填写来源说明**
   （例如“裁判组核分表”），该说明会同时记录为豁免原因，并在观众端持续显示——
   成绩不完整的名次只能由人负责，不能看起来像是算出来的。

因此：

- 确认一条成绩**不会**产生正式名次；名次也不会随单条成绩更正自动更新，
  更正后必须重新核对并重新定榜；
- 已确认但不完整、且没有人为来源的名次**不能发布**（校验报
  `ranking-confirmed-incomplete`）；
- 实时榜**不落库**、不进公开快照，也不参与任何业务判定。

### 轮次确认与冻结

每轮保存：轮次 ID、`matchIds`、输入截止轮次、该轮结果版本、确认时间、
**配对所依据的评分快照**、配对版本、公布时间、分组与槽位。

把「当前参考排名」和「已用于正式配对的排名」**分开**。

维护流程：

```
录入成绩 → 单场确认 → 全轮校验与确认 → 生成下一轮候选 → 检查 → 公布并冻结
```

网站可以自动算出候选，但**不能因为一次输入保存就自动对外宣布新的对阵**。

### 更正的三类情形

1. **下游尚未发布** —— 重算评分并重建候选，作废旧候选。
2. **下游已发布但未开赛** —— 先显示受影响范围，要求维护者依据裁判/组委会决定选择
   「保留已公布对阵并说明」或「作废旧版本并重新公布」。
   **没有处置记录时阻止导出正式版本。**
3. **下游已经开赛或有有效结果** —— 保持已经发生的参赛双方和比赛记录，
   **不能静默把旧比分移给另一支队**。标记依赖不一致并阻止自动推进；
   记录组委会修订结果后才可恢复发布。

### 跨队伍重算范围

瑞士轮评分跨队伍依赖历史对手，因此更正时必须：

1. 重算**该截止轮次的全部队伍**（不只是被更正的两队）。
2. 再比对**所有后续已公布轮次和最终种子**。

决赛则沿 `winner`/`loser` 依赖图检查**全部受影响下游**。

采用**一个新的赛事数据版本整体保存**更正和处置，
不留下「新比分配旧种子但无说明」的半状态。
取消、重赛和行政结果用明确类型表达；**不删除历史数据后假装从未发生**。
